# Real-Data Validation Fixtures — Provenance & License

These are **real, third-party assets**, checked into the repository deliberately
(unlike `test_assets/`, which is synthetically generated at runtime) so that
IntelX's detectors are validated against genuine photographs and a genuine
pretrained model, not only against fixtures built to be caught. This directly
answers the gap flagged during hardening review: every detector had previously
only ever been exercised against synthetic data.

## Images (`images/`)

- **Source**: 40 images from the official COCO 2017 training set, fetched
  directly from the official COCO CDN (`http://images.cocodataset.org/train2017/`)
  — not via any third-party mirror or tool.
- **Selection**: the first 40 image IDs listed in Ultralytics' public
  `coco128` asset manifest were used only to identify 40 valid, genuinely
  diverse COCO image IDs; **no bytes from that (GPL-3.0-licensed tooling)
  zip were kept or redistributed** — every image here was independently
  re-downloaded from the official COCO CDN under COCO's own terms.
- **License**: COCO annotations are CC BY 4.0 (Creative Commons Attribution
  4.0 International, per https://cocodataset.org/#termsofuse). Images are
  subject to the original photographer's copyright; the COCO Consortium
  distributes them for research use under the same terms academic computer
  vision research has used for a decade. No annotation JSON is bundled here
  — this fixture set is used for unsupervised/self-referential checks
  (duplicate detection, OOD, embedding-space drift) and for real-model
  inference, not for label-accuracy grading against official ground truth.
- **Split**: `images/` contains the full 40-image pool. Validation code
  splits it into a 20-image "reference" batch and a 20-image "observed"
  batch (see `tests/test_real_world_validation.py`) so distribution-shift
  and OOD baselines are drawn from two genuinely different real-world
  samples, not the same 40 synthetic images compared against themselves.

## Model (`models/yolox_nano.onnx`)

- **Source**: official YOLOX-Nano ONNX export, Megvii-BaseDetection,
  downloaded directly from
  `https://github.com/Megvii-BaseDetection/YOLOX/releases/download/0.1.1rc0/yolox_nano.onnx`.
- **License**: Apache License 2.0 (YOLOX, Megvii). Permissive, no copyleft
  obligation — consistent with this project's declared license posture
  (see `/SBOM.md`) of avoiding AGPL/GPL entanglement (the reason this
  project does **not** use Ultralytics' YOLO code or weights, which are
  AGPL-3.0-licensed).
- **SHA-256**: `c789161ed43c8269fcd4e67c67eeeb4e80c622da2eb296a20bc6007bd18a0b7d`
  — re-verify with `shasum -a 256 real_validation/models/yolox_nano.onnx`
  before trusting this file; this is exactly the kind of digest check
  `backend/model_assurance/fingerprint.py` performs on every model IntelX
  assesses.
- **Architecture**: 904,482 parameters, 369 ONNX operators, opset 11.
  Input: `[1, 3, 416, 416]` (BGR, letterboxed/padded, unnormalized 0-255
  pixel values — see `backend/inference/inference_engine.py:
  preprocess_image_with_ratio` for the exact contract). Output:
  `[1, 3549, 85]` (multi-stride anchor grid: 4 box + 1 objectness + 80 COCO
  class logits, decoded by `InferenceEngine._decode_yolox_family`, a
  verified port of Megvii's own `yolox.utils.demo_utils.demo_postprocess`).
- **Not a backdoored/tampered variant.** This is the trusted, official,
  as-released checkpoint. It has no synthetic trigger. Backdoor/trigger
  behavioural testing continues to use IntelX's own synthetic
  clean-vs-backdoored ONNX fixture pair (`test_assets/models/`), which
  *is* purpose-built with a real, verifiable trigger response — this real
  YOLOX model instead validates that **the rest of the pipeline** (digest
  fingerprinting, duplicate/OOD/drift detection, real inference decoding)
  works correctly against a real, unmodified, third-party artifact.

## Reproducing this fixture set

```bash
# Images: pick any 40 real COCO train2017 image IDs and fetch them directly.
for id in 000000000009 000000000025 ...; do
  curl -sL -o "real_validation/images/${id}.jpg" \
    "http://images.cocodataset.org/train2017/${id}.jpg"
done

# Model:
curl -sL -o real_validation/models/yolox_nano.onnx \
  "https://github.com/Megvii-BaseDetection/YOLOX/releases/download/0.1.1rc0/yolox_nano.onnx"
```

Both are one-time, non-generative downloads (unlike `test_assets/`, which is
freshly regenerated by `AssetGenerator` on every run) — they're checked into
the repository so the air-gapped test suite doesn't depend on network access
at run time, per the PRD's offline-operation constraint (`AGENTS.md`
notwithstanding — this data is fetched once, ahead of time, exactly like the
"pre-provisioned wheels" model already used for Python dependencies).
