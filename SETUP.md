# VIGIL-CV — Setup & Run Notes

Problem Statement 26228 (Ministry of Defence / Indian Army DGIS). This document is the practical
"how do I actually run this" companion to `README.md`.

## 1. Requirements

- Python 3.11+ (tested on 3.11 and 3.14)
- Node.js 18+ / npm
- No internet access is required at runtime — the system is fully offline/air-gapped. Internet
  access is only needed once, up front, to install the Python and npm dependencies below.

## 2. Backend setup

```bash
cd backend
python3 -m venv .venv
source .venv/bin/activate
pip install -r requirements.txt
```

Run the API server:

```bash
uvicorn backend.main:app --host 0.0.0.0 --port 8000
```

(run from the repo root, with the venv above active, so the `backend` package resolves).

Verify it's up:

```bash
curl http://localhost:8000/health
```

Run the test suite:

```bash
pytest tests/ -v
```

## 3. Frontend setup

```bash
npm install
npm run dev
```

Open `http://localhost:3000`. The dashboard has two modes:

- **Scenario Replay** — four canned, reproducible attack scenarios (clean baseline, poisoned
  dataset, backdoored/substituted model, tampered inference record) generated fresh on first run
  under `test_assets/`.
- **Live Analysis** — upload your own ONNX/PyTorch/TorchScript model, a zipped COCO or YOLO
  dataset, and/or an image, and the exact same backend pipeline runs against your real files.

Set `NEXT_PUBLIC_API_URL` if the backend isn't at `http://localhost:8000`.

## 4. Runtime data locations

These are created automatically and are gitignored (do not commit them):

| Path | Purpose |
|---|---|
| `uploads/` | Files uploaded via the Live Analysis API (models, dataset archives, probe images) |
| `keys/provenance_signing_key.pem` | Persisted Ed25519 private key used to sign inference provenance records. Generated on first run if absent. Back this up if you need old signatures to remain independently verifiable after a redeploy. |
| `audit_log/ledger.jsonl` | The persisted, hash-chained tamper-evident audit ledger. Append-only; do not hand-edit. |
| `test_assets/` | Synthetic COCO/YOLO dataset + ONNX models generated by the scenario harness (`backend/scenarios/asset_generator.py`) |

## 5. Key API endpoints

| Method | Path | Purpose |
|---|---|---|
| POST | `/api/model/upload` | Upload a real model file, get back a real SHA-256 fingerprint |
| POST | `/api/model/parameter-analysis` | Real ONNX weight-statistics analysis (white-box only) |
| POST | `/api/model/behaviour-battery` | Real reference-vs-candidate model behavioral comparison |
| POST | `/api/dataset/upload` | Upload a zipped COCO/YOLO dataset |
| POST | `/api/dataset/analyze-profile` | Run the full data-integrity pipeline on a real dataset |
| POST | `/api/inference/execute` | Run a real model against a real image, get a signed provenance record |
| POST | `/api/inference/verify` | Verify a provenance record's cryptographic binding |
| GET  | `/api/audit/entries` | Read the full tamper-evident audit trail |
| POST | `/api/report/generate` | Compile findings into a governance-ready `AssuranceReport` |
| GET/POST | `/api/scenarios/list`, `/api/scenarios/run/{id}` | Canned reproducible attack scenarios A–D |

Full interactive API docs are available at `http://localhost:8000/docs` once the backend is running.

## 6. Reproducing the test scenarios manually

```python
from backend.scenarios.scenario_manager import ScenarioManager
mgr = ScenarioManager()
mgr.run_scenario_a_clean()             # clean baseline
mgr.run_scenario_b_poisoned()          # poisoned dataset / malicious contributor
mgr.run_scenario_c_model_compromised() # substituted + backdoored model
mgr.run_scenario_d_tampered_inference()# post-hoc inference tampering
```

Each call appends real, hash-chained entries to the shared audit ledger (`backend/audit/audit_log.py:shared_ledger`) — see `docs/example_audit_log.json` for a captured example spanning all four scenarios end-to-end.
